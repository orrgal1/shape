## Goal
A tiny CLI to drive a *running* visual-harness bridge over its WebSocket, so external tooling (the upcoming onboarding skill, scripts) can retarget the bridge and trigger onboarding without the web UI.

## Change
New file `packages/bridge/scripts/ctl.mjs` (plain Node, no deps beyond `ws`/built-ins — match how `scripts/fake-omp.mjs`/`smoke.mjs` do ws). Connects to `ws://localhost:<port><BRIDGE_WS_PATH>` (defaults from `packages/shared/src/index.ts`: port 4400, path `/ws`).

Commands (fixed contract — the skill issue #3 depends on exactly this):
- `node packages/bridge/scripts/ctl.mjs status` — wait for the bridge `hello`/session frame, print one JSON line: `{ok:true, cwd, sessionName?, worktrees?}` (whatever SessionInfo exposes; at minimum the target cwd).
- `node packages/bridge/scripts/ctl.mjs switch-project <abs-path>` — send `{type:"switch_project", path}`, wait for the re-hello confirming the new cwd, print `{ok:true, cwd}`.
- `node packages/bridge/scripts/ctl.mjs onboard [--focus "<text>"]` — send `{type:"onboard", focus?}`, print `{ok:true}` once accepted (don't wait for the survey turn to finish).
- Global flag `--port <n>` (default 4400).

Exit codes: 0 success; 2 when no bridge is listening (connection refused/timeout ~3s) with `{ok:false, error:"no bridge"}` on stdout.

## Acceptance
- With `pnpm bridge` running against this repo: `status` prints the cwd; `switch-project` to another checkout re-hellos and prints the new cwd; `onboard` returns ok.
- Without a bridge: each command exits 2 within ~3s.
- Do NOT run project-wide test suites/formatters; verify with the commands above (fake-omp/smoke harness may be used to avoid a real omp).

## Result
Merged to main as 156cc90: `packages/bridge/scripts/ctl.mjs`. Verified against a live bridge (fake-omp, seeded temp workspaces): `status` prints cwd/sessionName/worktrees; `switch-project` re-hellos with the new cwd (bad path → `{ok:false,…}` exit 1); `onboard --focus` accepted and the survey prompt reached omp. Without a bridge every command prints `{ok:false,error:"no bridge"}` and exits 2 within ~1s.
