Recommended by builder2 while working #8: pnpm 11 writes an `allowBuilds` placeholder into `pnpm-workspace.yaml` on fresh worktree installs, and esbuild's postinstall build is ignored until approved — this silently broke verification in a fresh issue worktree.

## Change
Commit the build approval (e.g. `pnpm approve-builds` for esbuild, or the equivalent `allowBuilds`/`onlyBuiltDependencies` entry in `pnpm-workspace.yaml`) so a fresh clone/worktree `pnpm install` yields a working esbuild without interactive approval. Verify no stray placeholder churn is left in the file.

## Acceptance
- In a fresh git worktree of this repo, `pnpm install` completes with esbuild built/approved, no interactive prompt, and `pnpm web` starts.
- `git status` clean after install (no self-rewriting pnpm-workspace.yaml churn).
- No project-wide suites/formatters.

## Result
Merged to main at 20ba74c. pnpm 11.6.0 ignores `onlyBuiltDependencies` and demands an `allowBuilds` map; replaced it with `allowBuilds: { esbuild: true }` in pnpm-workspace.yaml. Verified in a fresh worktree: `pnpm install` exits 0 with no prompt and no placeholder churn (git status clean), esbuild 0.28.2 binary built, and `pnpm web` (vite 7) serves HTTP 200. Note: default port 5173 was occupied by another running dev server during verification; smoke ran on `--port 5199`.
