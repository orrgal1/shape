## Goal
The onboarding skill must ship with the repo so anyone who clones visual-harness gets it. The repo copy is the single source of truth; the global `~/.claude/skills/visual-harness/` becomes an installed symlink to it.

## Change
1. Move the skill content from `~/.claude/skills/visual-harness/` into the repo at `skills/visual-harness/` (SKILL.md + any helper script), preserving behavior.
2. De-hardcode the harness checkout path: the skill dir now lives inside the harness repo, so resolve the checkout as the skill directory's own repo root (skill dir is `<checkout>/skills/visual-harness/` → checkout = two levels up; a helper script can use its own location, SKILL.md can say "the repo this skill ships in"). No `/Users/orgal/...` anywhere in the shipped files.
3. Install step: replace the user's existing `~/.claude/skills/visual-harness` with a symlink to the repo's `skills/visual-harness` (do this on this machine now). Document the one-liner install (`ln -s "$PWD/skills/visual-harness" ~/.claude/skills/`) in SKILL.md or a short note in HANDOFF.md's run section — whichever the repo convention favors; do not create a new README.

## Acceptance
- `skills/visual-harness/SKILL.md` exists in the repo, path-portable (no absolute user paths).
- `~/.claude/skills/visual-harness` is a symlink into the repo and the skill still resolves (readable through the symlink).
- Smoke: from a directory outside the repo, the skill's steps still work as written (bridge/web start-or-reuse, ctl retarget). Do NOT run project-wide test suites/formatters.
