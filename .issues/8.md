## Change
Archify's renderings identify component types with distinct symbols (REST API, database, queue, UI, service, ...) and generally look better than our plain bubbles. Adapt that:

1. Study how archify classifies components and which glyph/badge/shape treatment each type gets (its renderers/ dir; MIT — attribution if anything is copied verbatim).
2. Pick a small type vocabulary that fits our GraphDoc (packages/shared/src/index.ts) — e.g. extend the node model with an optional `kind`/`icon` field the agent can set via canvas ops, plus cheap heuristics as fallback (name/summary/codeRefs hints like "api", "db", "store", "ui").
3. Render the symbol on BubbleNode (packages/web/src/canvas/BubbleNode.tsx) as a badge/glyph consistent with the existing bubble styling — adapt the visual idea, don't transplant archify's whole look.
4. If the node model gains a field: update the canvas tool schema/description (shared + bridge preamble) so agents know they can set it; unknown values degrade to the default bubble.

## Acceptance
- At least 5 distinct type symbols render on `?mock=1` (extend mock data with typed nodes to demonstrate).
- Untyped nodes look exactly as before.
- If schema extended: a canvas op setting the type field round-trips through applyOps and renders.
- Visual verification via browser on the mock dataset; no project-wide suites/formatters.
