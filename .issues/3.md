## Goal
From ANY repo, invoking the skill gets that repo onto the visual-harness canvas: bridge + web running, bridge targeted at the repo, canvas open, onboarding survey triggered. Deliberately decoupled from the issue-lead/worker skills.

## Where
`~/.claude/skills/visual-harness/` — `SKILL.md` (frontmatter: name + a description that triggers on "onboard this repo to visual harness", "open the canvas for this project", "map this project visually") plus any helper script(s). Harness checkout path: `/Users/orgal/code/visual-harness` (hardcode; single-user machine — but put it in one obvious variable at the top of the script so it's editable).

## Behavior (what SKILL.md must instruct the invoking agent to do)
1. Resolve target = `git rev-parse --show-toplevel` else `$PWD`.
2. Bridge running? (TCP check on 4400) —
   - not running → start it as a managed background process (hub `op:"start"`, name `vh-bridge`): `pnpm bridge -- --cwd <target>` from the harness checkout, ready when ws port 4400 accepts.
   - running → retarget: `node packages/bridge/scripts/ctl.mjs switch-project <target>` (contract per issue #2: prints one JSON line `{ok:true, cwd}`, exit 2 = no bridge).
3. Web running? (TCP 5173) — else hub-start `vh-web`: `pnpm web` from the harness checkout.
4. Trigger onboarding: `node packages/bridge/scripts/ctl.mjs onboard [--focus "<user's focus, if they gave one>"]`.
5. Tell the user the canvas is live at http://localhost:5173 (and to watch the survey stream in).

Also cover in SKILL.md: repos with an already-populated `.visual-harness/graph.json` (skip onboard, just retarget + open); non-TS/non-pnpm repos (onboarding degrades to pure agent survey — that's expected, per onboarding.md).

## Constraints
- ctl.mjs is being built in parallel (issue #2). Code against the contract above; do NOT modify bridge sources. If ctl.mjs isn't on disk yet when you finish, that's fine — verify everything except the ctl calls, and note it.
- Read `onboarding.md` and `HANDOFF.md` (run instructions, line ~88) in the harness repo first.
- Keep it one skill, small: SKILL.md + at most one launcher/helper script.

## Acceptance
- Skill files exist and SKILL.md's steps are runnable as written (correct paths, correct pnpm invocations verified against the harness repo's package.json scripts).
- Smoke: from a different directory, following the skill's steps starts bridge+web (or reuses them) and http://localhost:5173 serves the canvas. Do NOT run project-wide test suites/formatters.
