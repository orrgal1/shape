## Bug
The directory-selection and branch-selection pop-ups (dropdowns in the web UI) stay open until the user clicks the same trigger button that opened them.

## Expected
- Clicking anywhere outside the open pop-up closes it.
- Pressing Escape closes it.
- Clicking the trigger button still toggles it (no double-toggle where an outside-click handler closes it and the button reopens it in the same click).

## Acceptance
- Open the directory pop-up, click elsewhere on the canvas/page → pop-up closes.
- Open the branch pop-up, press Escape → pop-up closes.
- Trigger button toggle still works for both pop-ups.
- Both pop-ups share the same dismissal mechanism (no copy-paste divergence).

## Result
Added a shared `useDismissable(open, setOpen)` hook in `packages/web/src/App.tsx` and wired it into both `ProjectSelector` and `VariationSwitcher` (ref on each `.project` wrapper). Document-level `pointerdown` closes on outside press; `keydown` Escape closes; listeners only attached while open. Trigger button sits inside the ref subtree, so its click is never "outside" — toggle keeps working with no double-toggle.

Verified: `tsc --noEmit` clean; browser smoke test on `?mock=1` with real mouse/keyboard — outside click closed the project pop-up, Escape closed the variation pop-up, both triggers toggle open/closed/open correctly.

Note: the web app is entirely untracked in git (main checkout has `packages/` as `??`), so a worktree from HEAD contained no code. Worked in place on the main checkout instead of a worktree/branch; there is no `issue/1` branch to merge — review the in-place diff in `packages/web/src/App.tsx`.
