## Change
`applyOps` (packages/shared/src/index.ts) rejections currently surface as flat prose ("rejected op 0: parent \"xyz\" does not exist"). Adopt archify's diagnostic shape so the agent can self-correct mechanically: each rejection becomes `{code, severity, message, subject, evidence, supportedFixes[]}` with paths annotated by the nearest enclosing node id/label (pattern: `archify/renderers/shared/diagnostics.mjs` and `validator.mjs`).

- Codes namespaced (e.g. `op/unknown-parent`, `op/cycle`, `op/bad-slug`), each with 1–3 concrete `supportedFixes` strings.
- Bridge canvas host tool serializes receipts as JSON in the tool result; keep a one-line human summary first.

## Acceptance
- Every rejection class in `applyOps` emits a receipt with code + subject + at least one supportedFix.
- A malformed op against a live bridge shows the receipt in the tool result.
- Existing accept path ("applied N op(s); rev=R") unchanged.
- No project-wide suites/formatters.

## Result
Merged to main (c96be2e). `OpRejection` is now a structured repair receipt
`{index, code, severity, message, subject, evidence, supportedFixes}` — every
applyOps rejection class carries a namespaced code (op/unknown-parent, op/cycle,
op/bad-slug, op/bad-phase, op/unknown-endpoint, ...) with 1-3 concrete fixes;
subject.path is annotated with the nearest enclosing node/edge id + label
(archify validator.mjs pattern). Onboarding gate vetoes emit receipts too
(onboarding/no-coderefs, onboarding/unknown-coderef). Bridge serializes
receipts as pretty JSON after the unchanged one-line summary
("applied N op(s); rev=R"). Verified live: fake-omp gained a bad-op turn
(unknown parent + bad phase + unknown op); smoke asserts the receipts in the
host_tool_result, error flag, and no rev bump — full smoke suite SMOKE OK,
bridge tsc clean.
